# 货币转换器应用：你的第一次 Vibe Coding 体验

> 不用自己写代码就能构建一个真实的应用。发现为什么**沟通清晰度**是 AI 辅助开发中最有价值的技能。

![Currency Converter App](img/currency-converter.png)

## 概述

在这节课中，你将体验 "vibe coding" —— 通过向 AI agent 描述你想要什么来构建软件，而不是手动编写代码。你将用三种不同的方式构建一个货币转换器应用，并发现一个根本性的真理：**你的输入质量直接决定了 AI 输出的质量**。

这不是在学一门编程语言。而是在学如何有效地与 AI 编程 agent 沟通 —— 这项技能正变得和编程本身一样有价值。

---

## 学习目标

在本课结束时，你将能够：

1. **亲身体验 vibe coding** —— 通过描述你想要的东西来构建一个可用的应用
2. **发现为什么清晰的需求很重要** —— 对比模糊与精确指令的差异
3. **学习访谈技巧** —— 使用 AI 来澄清你自己模糊的想法
4. **理解沟通瓶颈** —— 认识到 "构建什么" 比 "怎么构建" 更重要

## 你将构建什么

一个使用 Python 和 Streamlit 构建的简单货币转换器 Web 应用：

- 输入金额（例如 100）
- 选择源货币（例如 USD）
- 选择目标货币（例如 EUR）
- 即时查看转换结果

该应用故意做得很简单 —— 大约 30 行 Python 代码。重点不在于代码本身，而在于你如何沟通你想要什么。

## 练习

### 练习 1：模糊方式

**目标：** 体验当你给 AI 一个模糊的一句话请求时会发生什么。

**操作步骤：**

1. 启动 Gemini CLI：
   ```bash
   gemini
   ```

2. 用一个模糊的请求使用教学命令：
   ```
   /teach-code 帮我构建一个货币转换器
   ```

3. 让 Gemini 根据你模糊的请求构建它所理解的东西。

4. 运行结果：
   ```bash
   streamlit run app.py
   ```

5. 与参考实现（`app-example.py`）对比。注意差异。

**你会发现：**

AI 会构建出*某些东西* —— 但它可能不符合你的设想。也许它是一个命令行工具而不是 Web 应用。也许它使用了不同的货币。也许缺少错误处理。

这就是核心教训：**模糊的输入产生不可预测的输出**。AI 没有错 —— 它只是用自己的假设填补了你留下的所有空白。

> **关键洞察：** "帮我构建一个货币转换器" 有数百种合理的解释。当你不明确指定你想要什么时，AI 就会替你选择 —— 它的选择可能与你的不一致。

---

### 练习 2：清晰规格方式

**目标：** 体验当你提供清晰的规格说明时，结果的巨大差异。

**操作步骤：**

1. 启动一个新的 Gemini 会话：
   ```bash
   gemini
   ```

2. 这次，将 Gemini 指向详细的规格文件：
   ```
   /teach-code READ app-spec.md to understand the currency converter app requirement, then write the python app at app.py, and teach me how to run it.
   ```

3. 运行结果：
   ```bash
   streamlit run app.py
   ```

4. 与练习 1 的结果对比。注意这次与参考实现的差距有多小。

**你会发现：**

有了清晰的规格（`app-spec.md`），AI 产出的东西与你真正想要的更加接近。同样的 AI，同样的任务，截然不同的结果 —— 唯一的区别在于你输入的质量。

> **关键洞察：** 规格文件（`app-spec.md`）只有大约 40 行。编写一份清晰的规格需要 5-10 分钟，但能节省数小时的反复沟通。对人类开发者也一样 —— 前期的清晰能避免后期的混乱。

---

### 练习 3：访谈技巧

**目标：** 学习当你还*不知道*自己想要什么时该怎么做。

这是本课中最强大的技巧。有时你只有一个模糊的想法 —— "我想做一些跟货币相关的东西" —— 但还没想清楚细节。与其瞎猜，不如让 AI 成为你的头脑风暴伙伴。

**操作步骤：**

1. 启动一个新的 Gemini 会话：
   ```bash
   gemini
   ```

2. 用你的模糊想法使用头脑风暴命令：
   ```
   /teach-brainstorm 我想构建一个货币转换器应用，但不确定它应该有哪些功能或者怎么组织结构
   ```

3. 诚实地回答 Gemini 的问题。它会问你：
   - 你在解决什么问题？
   - 有哪些约束条件？
   - 你在优化什么？

4. 让对话自然地引导出一个清晰的计划。

5. 有了计划后，使用 `/teach-code` 来实现它。

**你会发现：**

访谈技巧通过对话将模糊的想法转化为具体的计划。你不需要在开始之前就有所有答案 —— 你只需要愿意思考这些问题。

> **关键洞察：** 访谈技巧的价值超越了 AI 工具本身。当同事说 "我想构建 X" 时，最优秀的工程师不会直接开始写代码 —— 他们会先问澄清问题。这是同一种技能。

## 核心概念

### 沟通瓶颈

在传统软件开发中，瓶颈通常是 "怎么实现" —— 写代码、调试、理解框架。AI 工具消除了大部分这种阻力。

但一个新的瓶颈出现了：**"实现什么"**。AI 可以构建你清楚描述的任何东西。挑战在于如何清楚地描述它。

这就是为什么沟通技能 —— 精确思考、清晰写作、提出好问题 —— 正变得和编程技能一样有价值。

### 输入质量的频谱

```
模糊的输入            →  不可预测的输出
↓                        ↓
"帮我做个东西"        →  "给你一个东西（可能不是你想要的）"

清晰的输入            →  可预测的输出
↓                        ↓
"用 Y 和 Z 构建 X，  →  "这就是使用 Y 和 Z 的 X"
 使用..."
```

### 访谈技巧

当你不知道自己想要什么时：

1. **从模糊想法开始** —— "我想做一些跟货币相关的东西"
2. **让 AI 提问** —— 使用 `/teach-brainstorm` 开始结构化对话
3. **诚实回答** —— "我不确定" 是一个合理的回答
4. **收敛到计划** —— 问题会自然引导出清晰的方向
5. **清晰执行** —— 现在用 `/teach-code` 配合你的清晰计划

这个技巧之所以有效，是因为这些问题迫使你思考你可能忽略的方面。

## 反思

完成所有三个练习后，思考以下问题：

1. **哪种方式产生了最好的结果？** 为什么？
2. **写规格花了多长时间 vs. 节省了多少时间？**
3. **你会在什么时候使用每种方式？**
   - 模糊方式：快速实验、探索
   - 规格方式：已知需求、生产代码
   - 访谈方式：需求不明确、早期想法阶段

元教训：AI 不能替代思考 —— 它放大思考。清晰的思考产生清晰的输出。模糊的思考产生模糊的输出。

## 导师寄语

**为什么这节课比你想象的更重要：**

我观察过数百人第一次尝试 AI 编程工具。模式总是一样的：

1. 他们输入一些模糊的东西
2. 他们得到一些意想不到的结果
3. 他们要么怪 AI（"它不够聪明"），要么怪自己（"我不擅长这个"）

两者都不对。问题始终在于**他们想象的和他们沟通的之间的差距**。

这节课就是为了让那个差距变得可见。当你把练习 1 的结果和练习 2 的结果放在一起看时，这个教训会强烈地击中你 —— 不是作为一个抽象的原则，而是作为一种亲身体验。

**访谈技巧才是这里真正的宝藏。** 在专业软件开发中，最困难的部分往往是弄清楚要构建什么。需求是模糊的。利益相关者意见不一。没有人有完整的画面。能够提出正确的问题 —— 将模糊的想法转化为具体的计划 —— 是行业中最有价值的技能之一。

你刚刚用 AI 作为对话伙伴练习了这项技能。

**下一步：**

在继续学习本课程的过程中，注意你在 prompt 中是模糊的还是清晰的。你越多练习与 AI 的清晰沟通，你的结果就越好 —— 而且你的整体沟通能力也会随之提升。

## 快速参考

**启动 Gemini CLI：**
```bash
gemini
```

**教学命令：**
```
/teach-start          # 开始引导式学习
/teach-code           # 写代码 + 获得学习笔记
/teach-brainstorm     # 通过对话澄清模糊想法
/teach-check          # 根据清单验证你的工作
/teach-explain        # 理解代码或概念
/teach-debug          # 调试错误 + 学会读 stack trace
```

**运行应用：**
```bash
streamlit run app.py           # 你的应用
streamlit run app-example.py   # 参考实现
```

**会话管理：**
```bash
gemini                # 启动新会话
gemini -r             # 恢复上次会话
gemini --resume       # 恢复上次会话（替代方式）
```

在 Gemini CLI 内部：
```
/resume               # 浏览并恢复之前的会话
```

**中文命令：** 添加 `-cn` 后缀（例如 `/teach-code-cn`、`/teach-start-cn`）
