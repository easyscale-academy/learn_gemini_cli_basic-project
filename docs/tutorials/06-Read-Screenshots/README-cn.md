# Gemini CLI 基础操作：用截图让 AI 理解你看到的界面

> 学会把截图分享给 Gemini CLI，让 AI 能看到错误信息、UI 元素和图表——就像给同事看你的屏幕一样。

## 概述

你遇到一个报错界面，想问 AI 怎么解决。你可以尝试用文字描述："就是那个红色的框，里面写了一堆英文，好像是什么 error..."

但这样描述既费劲又不准确。更好的方法：直接截图给 AI 看。Gemini CLI 可以"看懂"图片——错误信息、UI 界面截图、代码截图、流程图、架构图。学会用截图和 AI 沟通，能大大提高问问题的效率。

## 学习目标

回想一下上次你通过文字向别人描述 bug 的经历。你可能花了五分钟打字说明屏幕上的内容，结果对方说"你直接截个图给我吧？"截图能瞬间消除歧义。和 AI 合作也是一样的道理——与其费劲描述你看到的东西，不如直接给它看。

学完这节课，你将能够：

1. 截图并保存到项目中
2. 把截图上传到 Codespace 并获取文件路径
3. 把截图路径发给 Gemini CLI，让 AI 解读图片内容

## 前置条件

- 已安装并登录 Gemini CLI（前几节课完成的）
- 打开了这个项目的 GitHub Codespace
- 完成了第 04 课（用 `@` 读取文件）和第 05 课（读取 URL）

这次不需要写代码——这是一个技能练习。你会练习把截图分享给 Gemini CLI，这对于调试错误、获取 UI 反馈、向 AI 传达视觉信息都至关重要。

## 核心概念

### 为什么截图比文字描述好

用文字描述错误时，你可能会漏掉关键细节——具体的错误代码、堆栈跟踪、或者 UI 中的上下文线索。截图能一次性捕获所有内容，完全还原你看到的样子。AI 能读取图片中的文字、识别 UI 元素、理解布局，甚至解读图表。

### 工作流程：从截图到 AI

这个过程有四个步骤：

1. **截图** — 在电脑上截取屏幕
2. **上传** — 把截图上传到 Codespace（如果在浏览器中工作）
3. **复制路径** — 获取截图的文件路径
4. **发给 AI** — 在 Gemini CLI 中用 `@` 引用截图路径并提问

### 怎么截图

**在 Mac 上：**
- `Cmd + Shift + 4` — 拖动选择区域截图
- 截图会自动保存到桌面（或你设置的默认位置）

**在 Windows 上：**
- `Win + Shift + S` — 拖动选择区域截图
- 截图保存到剪贴板——你需要粘贴到文件中保存

**在 Codespace 中（浏览器里）：**
- 使用操作系统自带的截图工具
- 把截图保存到你能找到的地方

### 怎么上传到 Codespace

如果你在浏览器中使用 Codespace，需要把截图上传进去：

1. 在左侧 Explorer 面板中，找到你想放截图的文件夹
2. **右键点击文件夹 → 选择 "Upload..."**
3. 选择你刚才保存的截图文件
4. 等待上传完成

### 怎么获取文件路径

截图上传到 Codespace 后：

1. **右键点击截图文件** — 在 Explorer 面板中
2. **选择 "Copy Relative Path"**

你会得到类似 `img/error-message.png` 这样的路径。然后在 Gemini CLI 中用 `@` 引用它，就像引用其他文件一样。

## 练习

### 练习 1：让 AI 描述你的屏幕

**目标：** 截一张 Codespace 的图，让 Gemini CLI 描述它看到了什么。

**步骤：**

1. 对你当前的 Codespace 屏幕截图——文件树、编辑器、终端，随便什么
2. 把截图上传到项目中（右键文件夹 → Upload）
3. 右键上传的文件 → Copy Relative Path
4. 打开 Gemini CLI，输入：

```
Look at this screenshot and tell me what interface is shown: @img/your-screenshot.png
```

（把 `img/your-screenshot.png` 换成你实际的文件路径）

5. 按 Enter 发送

**你会看到：**

Gemini 会描述它看到的内容——比如"这是 VS Code 编辑器，左侧的 Explorer 面板显示了项目的文件结构..."它能读取文字、识别 UI 元素、理解布局。

> **关键要点：** AI 能"看"图片，就像它能读文本文件一样。截图给它提供了文字无法传达的视觉上下文。

---

### 练习 2：让 AI 帮你看错误信息

**目标：** 截一个错误信息的图，让 Gemini CLI 解释并给出解决方案。

**步骤：**

1. 找到或触发任何开发环境中的错误信息（终端报错、浏览器错误、代码检查警告——什么都行）
2. 只截错误部分的图
3. 上传到 Codespace 并复制相对路径
4. 在 Gemini CLI 中输入：

```
Look at this screenshot and tell me what this error means and how to fix it: @img/your-error.png
```

5. 按 Enter 发送

**你会看到：**

Gemini 会从图片中读取错误信息，解释它是什么意思，并建议如何修复。这通常比手动复制错误文本更快，特别是对于包含多个信息的复杂错误对话框。

> **关键要点：** 调试时，截图是获得帮助的最快途径。AI 能读取错误文本、识别错误代码、看到周围的上下文——全部来自一张图。

## 回顾：我们学到了什么？

- 工作流程是：**截图 → 上传到 Codespace → 复制相对路径 → 用 `@` 发给 Gemini CLI**
- Gemini CLI 能"看懂"图片——错误信息、UI 元素、代码、图表
- 截图比文字描述更快、更准确
- 用 `@` 加截图的相对路径，和引用其他文件的方式一样

## 导师寄语

**为什么这个练习很重要：**

你现在有三种方式给 AI 提供上下文了：本地文件（`@`）、网页 URL、截图。三者结合起来，几乎能覆盖所有你需要 AI 理解某样东西的场景。文件用于代码，URL 用于文档，截图用于视觉信息。这就是给 AI 提供上下文的完整工具包。

**核心洞察：**

- 截图消除了"信息丢失"的问题。当你让 AI 看到你看到的完全一样的东西时，就不会有沟通偏差。这在调试时尤其有价值——AI 看到和你一样的错误，所有细节都完整保留。
- 我认识的最优秀的开发者都是出色的沟通者。用截图和 AI 沟通也是如此——清晰、精确的上下文带来清晰、精确的回答。

**下一步：**

养成习惯：每当你遇到视觉问题——错误弹窗、排版异常、看不懂的 UI——截图丢给 Gemini CLI。你会惊讶于一张截图多久就能帮你拿到答案。

## 快速参考

**截图工作流程：**
1. 截图（Mac: `Cmd+Shift+4`，Windows: `Win+Shift+S`）
2. 上传到 Codespace（右键文件夹 → Upload）
3. 复制相对路径（右键文件 → Copy Relative Path）
4. 发给 Gemini CLI：`@img/screenshot.png`

**示例提示：**
```
What does this error mean? @img/error.png
Describe what you see in this screenshot: @img/screen.png
What's wrong with this UI? @img/broken-layout.png
```

**截图最佳实践：**
- 保持文字清晰可读——不要截太小
- 只截相关区域，不要截整个屏幕
- 用描述性文件名如 `error-npm-install.png`，不要用默认的 `Screenshot 2024-01-15.png`
