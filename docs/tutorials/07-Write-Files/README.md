# Gemini CLI Basics (Part 4): Directing AI Output Exactly Where You Want It

> Learn how to tell Gemini CLI exactly where to write files, and have it document every change along the way.

## Overview

So far you've learned how to feed context into Gemini CLI — files, URLs, and screenshots. But what about the output side? When Gemini writes code or creates files, where does it all go?

In this lesson, you'll learn to control the output: tell Gemini exactly where to save files, and have it produce a changelog so you always know what changed and why.

## Learning Objectives

When you work with an AI coding agent, the conversation doesn't end when the AI writes some code. If you don't tell it where to put things, you're stuck copying and pasting. And if it modifies existing code without documenting what it changed, you're left guessing.

The fix is simple: always specify output paths, and always ask for a changelog. This turns AI from a black box into a transparent collaborator.

By the end of this exercise, you will:

1. Use absolute paths to direct Gemini CLI output to specific file locations
2. Have Gemini CLI generate changelog documents that explain what it did and why
3. Establish a workflow for tracking AI-driven changes in your projects

## Prerequisites

- Gemini CLI installed and authenticated (completed in lessons 02 and 03)
- A project workspace open in your terminal
- Familiarity with feeding files to Gemini CLI using `@` (lesson 04)

## What You'll Build

You'll create a Python script and an accompanying documentation file, all generated by Gemini CLI and saved to locations you specify. You'll also set up a `docs/changes/` folder for tracking AI modifications.

## Key Concepts

### Specifying the Output Path

When you ask Gemini CLI to create or modify files, use absolute paths to be explicit about where things go.

**Creating a new file:**

```
Write me a simple Python script that prints "Hello World"
Save it to /workspaces/my-project/scripts/hello.py
```

**Modifying an existing file:**

```
Modify /workspaces/my-project/src/config.json
Change the debug field from false to true
```

Gemini CLI will create or modify the file right where you specified — no manual copy-paste needed.

The key idea: **you are the one who decides where files go, not the AI.** This keeps your project organized and predictable.

### Having AI Write a Changelog

Here's an incredibly useful practice: **every time AI makes changes, have it write a summary document.**

Why bother?

- **Learning opportunity:** When AI explains what it changed and why, you absorb the underlying principles
- **Traceability:** You can look back later and see exactly what each change was about
- **No more black boxes:** You'll never be in the "AI changed something, but I have no idea what" situation

To do this, append something like this to your request:

```
After you're done, create a markdown file in /workspaces/my-project/docs/changes/
that documents:
1. Which files you changed
2. What specifically was changed
3. Why you made those changes
4. The underlying concepts or principles involved
```

### Putting It Together: A Full Example

Here's what a complete request looks like:

```
Optimize the database queries in /workspaces/my-project/src/api/user.py
to reduce the number of queries being made.

When you're done, create a file called optimize-user-query.md
in /workspaces/my-project/docs/changes/ that documents:
1. What you changed
2. How you changed it
3. Why these changes improve performance
4. The relevant database query principles
```

Gemini CLI will:

1. Modify the code file you specified
2. Create a detailed changelog document

Two outputs from one request — the work gets done and the reasoning gets captured.

### Building a Changelog Habit

Set up a dedicated folder in your project for changelogs:

```
my-project/
├── src/           # Source code
├── docs/          # Documentation
│   └── changes/   # AI changelogs
├── scripts/       # Scripts
└── ...
```

Every time AI makes a significant change, have it create a record in `docs/changes/`.

**Naming suggestions:** Use dates or task names:

- `2024-01-15-fix-login-bug.md`
- `optimize-database-query.md`
- `add-user-authentication.md`

## Exercises

### Exercise 1: Create a Script with Documentation

**Goal:** Have Gemini CLI create a file and write an accompanying documentation file, both at locations you specify.

**What to do:**

1. Open Gemini CLI in your terminal
2. Enter the following (adjust the project path to match yours):

```
Create a simple Python script:
- Save it to /workspaces/[your-project-name]/scripts/greet.py
- It should accept a name as an argument and print "Hello, [name]!"

Then create a file called greet-script-notes.md
in /workspaces/[your-project-name]/docs/ that explains:
1. What this script does
2. How to run it
3. What Python concepts the code uses
```

3. Press Enter to send

**What you'll notice:**

- Gemini CLI creates the `greet.py` script at the path you specified
- It also creates the `greet-script-notes.md` documentation file
- Both new files appear in your file browser at the exact locations you chose

> **Key insight:** You controlled both outputs — the code and its documentation — with a single prompt. This is how you keep AI output organized and traceable.

## Reflection: What Did We Learn?

The complete AI collaboration workflow ties together everything from this series:

1. **Input — Give AI the context it needs:**
   - Use `@` with file paths so AI can read the relevant code
   - Use URLs so AI can read reference documentation
   - Use screenshots so AI can see the UI or error messages
2. **Process — Tell AI what to do:**
   - Be explicit about the task
   - Specify absolute paths for all output files
3. **Output — Have AI document its work:**
   - Request a changelog
   - Capture what was done, why, and the principles behind it

This way, you're not just getting tasks done efficiently — you're learning along the way and keeping a complete record of everything.
