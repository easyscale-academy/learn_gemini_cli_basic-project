# Gemini CLI 基础操作（四）：让 AI 输出到指定位置

## 为什么要学这个？

你让 AI 帮你写一段代码，AI 写完了... 然后呢？

如果你不告诉 AI 把代码放到哪个文件里，你就得自己复制粘贴。更糟糕的是，如果 AI 帮你改了代码但没说清楚改了什么，你都不知道它动了哪里。

**解决方案：明确告诉 AI 输出到哪里，并让它写一份"改动说明"。**

这是和 AI 协作的高级技巧：不仅让 AI 干活，还让它把干了什么、为什么这么干都记录下来。这样你既能学到东西，又能追溯历史。

---

## 指定输出路径

当你让 AI 创建或修改文件时，用绝对路径（absolute path）明确指定：

**创建新文件：**

```
请帮我写一个简单的 Python 脚本，功能是打印 "Hello World"
把它保存到 /workspaces/my-project/scripts/hello.py
```

**修改现有文件：**

```
请修改 /workspaces/my-project/src/config.json
把里面的 debug 字段从 false 改成 true
```

AI 会直接在指定位置创建或修改文件，你不需要手动复制粘贴。

关键点：**你来决定文件放在哪里，不是 AI。** 这样你的项目结构才是可控、可预期的。

---

## 让 AI 写"改动说明"

这是一个非常实用的技巧：**每次让 AI 改完东西后，让它写一份总结文档。**

为什么要这样做？

- **学习效果：** AI 解释它改了什么、为什么这样改，你能学到背后的原理
- **可追溯性：** 以后回头看，知道每次改动的目的和内容
- **避免黑箱：** 不会出现"AI 改了，但我不知道改了什么"的情况

### 怎么做？

在你的请求最后加上这段话：

```
改完之后，请在 /workspaces/my-project/docs/changes/ 目录下
创建一个 markdown 文件，记录：
1. 你改了哪些文件
2. 具体改了什么
3. 为什么这样改
4. 背后的原理是什么
```

### 完整示例

把"指定路径"和"写改动说明"结合起来，一个完整的请求长这样：

```
请帮我修改 /workspaces/my-project/src/api/user.py
优化里面的数据库查询，减少查询次数

改完之后，请在 /workspaces/my-project/docs/changes/ 目录下
创建一个文件叫 optimize-user-query.md，记录：
1. 你改了哪些地方
2. 具体怎么改的
3. 为什么这样改能优化性能
4. 相关的数据库查询原理
```

AI 会：

1. 修改你指定的代码文件
2. 创建一份详细的改动说明文档

一个请求，两个输出——活干了，原因也记录了。

## 建立你的改动记录习惯

建议在项目中创建一个专门存放改动说明的文件夹：

```
my-project/
├── src/           # 源代码
├── docs/          # 文档
│   └── changes/   # AI 改动记录 ← 专门放这个
├── scripts/       # 脚本
└── ...
```

每次让 AI 做重要修改时，都让它在 `docs/changes/` 下创建一份记录。

**命名建议：** 用日期或任务名命名，比如：

- `2024-01-15-fix-login-bug.md`
- `optimize-database-query.md`
- `add-user-authentication.md`

## 小练习：动手试一试

**目标：** 让 AI 创建一个文件，并写一份说明文档

**步骤：**

1. 打开 Gemini CLI
2. 输入以下内容（根据你的实际项目路径调整）：

```
请帮我创建一个简单的 Python 脚本：
- 保存到 /workspaces/[你的项目名]/scripts/greet.py
- 功能：接受一个名字作为参数，打印 "Hello, [名字]!"

创建完成后，请在 /workspaces/[你的项目名]/docs/ 目录下
创建一个文件叫 greet-script-notes.md，说明：
1. 这个脚本是干什么的
2. 怎么运行它
3. 代码里用到了什么 Python 知识点
```

3. 按 Enter 发送

**预期结果：**

- AI 会创建 `greet.py` 脚本，放在你指定的位置
- 同时创建 `greet-script-notes.md` 说明文档
- 你可以在文件浏览器中看到这两个新文件

> **关键收获：** 你用一条指令同时控制了两个输出——代码和文档。这就是让 AI 输出有序、可追溯的方法。

## 完整的"AI 协作"流程

把前面学的串起来，这就是和 AI 高效协作的完整流程：

1. **输入 - 让 AI 了解情况：**
   - 用 `@` + 文件路径让 AI 读取相关代码
   - 用 URL 让 AI 读取参考文档
   - 用 `@` + 截图让 AI 看到界面或错误
2. **处理 - 让 AI 干活：**
   - 明确告诉 AI 要做什么
   - 指定输出文件的绝对路径
3. **输出 - 让 AI 记录：**
   - 要求 AI 写改动说明
   - 记录做了什么、为什么、背后原理

这样，你不仅能高效完成任务，还能在过程中学到东西，并保留完整的记录。

---

## 小结

- 用**绝对路径**指定 AI 的输出位置
- 让 AI 写**改动说明文档**，记录改了什么、为什么
- 建立 `docs/changes/` 文件夹，养成记录改动的习惯
- 输入 → 处理 → 输出，形成完整的 AI 协作流程
