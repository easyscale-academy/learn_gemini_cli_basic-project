# 编辑长消息

> 学习如何使用 markdown 文件高效地撰写和编辑长消息，而不是直接在终端输入框中打字。

## 为什么要学这个

想象一下：你想问 Gemini CLI 一个详细的问题。你开始在终端里打字，但很快就变得很别扭。你在上面第三行打了个错字，只能全部重新输入。或者你想在一条 prompt 里同时包含代码片段、文件路径和具体指令。

在终端里直接输入长长的 prompt 是一件很痛苦的事。你容易思路中断，打过的内容不好改，而且一旦发送出去就没了——你没法复用或改进它。

解决办法？**先在文件里写好你的消息，然后粘贴到 Gemini CLI 里。** 这个简单的工作流改变，会极大地提升你与 AI 沟通的效率。

## 消息文件方法

不要直接在 Gemini CLI 中打字，而是在项目中创建一个文件 `.gemini/gemini-messages.md`。这个文件就是你的"草稿空间"，专门用来起草 prompt。

具体操作方式：

1. **打开** 编辑器中的 `.gemini/gemini-messages.md`
2. **在文件底部** 分隔线下方写你的消息
3. **复制** 这段消息
4. **粘贴** 到 Gemini CLI 中
5. **保留** 这个文件——你的消息历史都在里面

这个文件就像一个草稿本。你可以看到之前的 prompt，不断完善当前的提问，还能组织复杂的请求而不用跟终端较劲。

### 为什么放在 `.gemini/` 目录下？

`.gemini/` 目录在你的项目中已经存在了，用来存放配置文件。把消息文件放在这里能让一切保持整洁。如果你不想把草稿提交到版本控制，也很容易加到 `.gitignore` 里。

## 其他输入方式

Gemini CLI 还提供了不离开终端就能写长消息的内置方式：

### Shift+Enter / Ctrl+Enter — 多行输入

在 Gemini CLI 提示符下按 **Shift+Enter** 或 **Ctrl+Enter** 可以换行而不发送消息。这样你就能直接在终端里输入多行 prompt。

对于快速的多行消息非常方便——比如你需要两三行内容但不想专门打开文件的时候。

### Ctrl+X — 打开外部编辑器

按 **Ctrl+X** 可以打开你的默认文本编辑器（由 `$EDITOR` 环境变量设置）。在编辑器中写好完整的消息，保存并关闭后，内容会自动发送到 Gemini CLI。

这对于较长的结构化 prompt 来说非常理想。如果你习惯了 Vim、VS Code 或 Nano，这种方式会感觉很自然。

### 什么时候用哪种方式？

| 方法 | 适用场景 |
|------|----------|
| 直接输入 | 快速的单行问题 |
| Shift+Enter | 2-3 行的 prompt，快速格式化 |
| Ctrl+X | 较长的结构化 prompt，一次性的详细问题 |
| 消息文件 | 可复用的 prompt，保持历史记录，复杂的多部分指令 |

消息文件方法对于正式工作仍然是最有价值的——它让你保留 prompt 历史，并随着时间不断完善它们。

## 从上到下书写

使用消息文件时，始终在文件的**最底部**写新消息。使用分隔线（比如 `---` 或一排破折号）来直观地分隔不同的 prompt。

```markdown
------------------------------------------------------------------------------
我的第一条消息写在这里。
------------------------------------------------------------------------------
我的第二条改进后的消息写在这里。
------------------------------------------------------------------------------
最新的消息在最底部，随时可以复制。
------------------------------------------------------------------------------
```

这样，你的文件就变成了思考过程的记录。你可以向上滚动看 prompt 是怎么演变的，而最新的一条总是在底部，随时可以复制使用。

## 在消息中引用文件

在消息文件中撰写 prompt 时，你可以引用希望 Gemini 读取的项目文件。在 Gemini CLI 中，使用 `@` 加上相对路径来引用文件内容：

```
@src/main.py 请审阅这个文件并提出改进建议。
```

你可以引用多个文件：

```
@src/utils.py @src/config.py 比较这两个文件，解释它们是如何交互的。
```

把这段内容粘贴到 Gemini CLI 后，它会读取引用的文件并将其内容包含在对话中。

**提示：** 先在消息文件中写好这些引用文件的 prompt，这样你可以在发送前仔细检查路径。

## 清除输入和退出

几个需要知道的键盘快捷键：

- **Ctrl+C** — 取消当前生成或清除当前输入
- **Ctrl+D** 或输入 `exit` — 退出 Gemini CLI
- **开始新会话** — 直接再次运行 `gemini` 即可

与一些工具不同，Gemini CLI 中的 Ctrl+C 是取消当前操作而不是退出。当你想离开时，使用 Ctrl+D 或输入 `exit`。

## 动手练习

让我们来练习消息文件的工作流：

1. 在编辑器中打开 `.gemini/gemini-messages-example.md`
2. 观察文件结构——注意分隔线和底部的示例消息
3. 复制示例消息（最后两条分隔线之间的文字）
4. 在终端中打开 Gemini CLI
5. 粘贴消息并按 Enter
6. 观察 Gemini 的回复

现在自己试试看：

7. 回到示例文件
8. 在最后一条分隔线下面，写你自己的消息——关于这个项目的某个具体问题
9. 复制并粘贴到 Gemini CLI 中
10. 感受一下在编辑器里撰写 prompt 有多轻松

**加分项：** 在 Gemini CLI 中试试按 Ctrl+X 打开外部编辑器。在里面写一条消息，保存并关闭——看它自动发送出去。

## 常见问题

### "终端里粘贴不了"
不同的终端模拟器处理粘贴的方式不同。试试 Ctrl+Shift+V（Linux）、Cmd+V（Mac），或右键粘贴。在 VS Code 的集成终端中，通常 Ctrl+Shift+V 可以用。

### "消息太长了"
Gemini CLI 可以处理很长的 prompt，但如果你遇到了限制，试试把请求拆分成更小、更聚焦的问题。这通常也能得到更好的结果。

### "发送后消息丢了"
这正是消息文件方法的价值所在。你的草稿保留在文件里，即使粘贴发送之后也不会丢失。你的工作永远不会白费。

### "Ctrl+X 不能打开编辑器"
确保你设置了 `$EDITOR` 环境变量。例如，在你的 shell 配置文件（`.bashrc`、`.zshrc`）中添加 `export EDITOR=nano`（或 `vim`、`code --wait` 等）。

## 导师寄语：用心沟通

这件事可能会让你意外：**prompt 的质量比 AI model 的质量更重要。**

一条写得好的、具体的 prompt 发给一个快速的 model，几乎总是比一条模糊的、仓促的 prompt 发给一个强大的 model 效果更好。你花在撰写消息上的时间是一笔立刻就能见到回报的投资。

消息文件方法不只是一个方便的技巧——它是一种思维方式的转变。当你在编辑器里写 prompt 时，你自然而然会：

- 更仔细地思考你在问什么
- 提供更多上下文
- 更清晰地组织你的请求
- 发送前审查一遍

这些和让你成为更好的人类沟通者的技能一模一样——在代码审查、文档编写和团队讨论中都是如此。练习和 AI 用心沟通，就是在练习和所有人用心沟通。

**最好的 prompt，是你花时间想过的那一条。**
